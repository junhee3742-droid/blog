사실 저는 이미 블로그가 하나 있어요. 건강정보를 올리는 티스토리 블로그예요.

> "그럼 거기에 쓰면 되잖아?"

![고민](/stickers/thinking.svg)

저도 처음엔 그렇게 생각했어요. 이번 편은 시리즈의 "번외편"이에요. 블로그를 직접 만들기 **전에** 했던 고민, 즉 왜 블로그를 새로 만들었고 왜 하필 직접 만들었는지를 정리해 볼게요.

## 기존 블로그에 쓸까, 새로 만들까?

새로 쓰고 싶은 글은 이런 것들이었어요.

- 바이브 코딩으로 만든 논문 수집기
- 블로그 글쓰기 자동화
- 앱 만들기 같은 부업 프로젝트

Claude에게 물어보니 기준은 간단했어요. **주제가 같으면 기존 블로그, 완전히 다르면 새 블로그**예요.

| 기존 블로그에 쓰면 | 새로 만들면 |
| --- | --- |
| 쌓아 둔 방문자와 검색 신뢰도를 그대로 써요 | 검색 신뢰도가 0부터 시작해요 |
| 애드센스를 다시 받을 필요가 없어요 | 애드센스를 다시 받아야 해요 |
| 주제가 섞이면 검색엔진이 "이 블로그는 뭘 잘하지?" 헷갈려해요. 기존 건강 글 순위까지 흔들릴 수 있어요 | 주제가 분명해서 검색엔진과 독자 모두 이해하기 쉬워요 |

건강정보를 찾는 사람과 바이브 코딩에 관심 있는 사람은 완전히 다른 독자예요. 그래서 새로 만들기로 했어요.

## 쓰고 싶은 게 네 가지였어요

정리해 보니 쓰고 싶은 주제가 네 개였어요. 건강정보, 주식, 논문, 개발·부업이에요. 주제마다 블로그를 만들면 관리가 너무 힘들어서, **독자가 겹치는지**를 기준으로 묶었어요.

| 블로그 | 주제 | 이유 |
| --- | --- | --- |
| 기존 티스토리 | 건강정보 | 이미 쌓인 신뢰도를 그대로 둬요 |
| 새 블로그 A | 주식·재테크 | 독자, 검색어, 말투가 전부 달라요 |
| **Vibe Lab Notes** | 과학·연구 소식 + 개발·부업 | 아래에서 설명할게요 |

## 과학과 코딩을 한 블로그에?

![아이디어](/stickers/idea.svg)

언뜻 안 어울려 보이지만, 연결고리가 있어요.

- **논문 수집기**가 다리 역할을 해요. 논문을 다루는 도구를 바이브 코딩으로 만든 거니까요.
- 논문에 관심 있는 연구자·대학원생과 자동화에 관심 있는 사람은 **"일을 더 잘하고 싶은 사람"**이라는 공통점이 있어요.
- 무엇보다 신경과학을 공부하면서 AI로 도구를 만드는 **제 실제 모습**과 같아요.

그래서 블로그 이름도 연구 노트(Lab Notes)와 바이브 코딩(Vibe)을 합쳤어요.

## 티스토리, 벨로그, 직접 만들기

마지막 고민은 "어디에 만들까"였어요.

| | 티스토리 | 벨로그 | 직접 만들기 |
| --- | --- | --- | --- |
| 한국 검색 노출 | 가장 좋아요 | 보통 | 처음엔 0 |
| 애드센스 | 쉬워요 | 약해요 | 직접 붙여요 |
| 한/영 두 언어 | 어려워요 | 안 돼요 | 처음부터 설계 가능 |
| 관리 | 편해요 | 편해요 | 직접 해야 해요 |
| 만드는 과정이 글감? | 아니요 | 아니요 | **네!** |

결정적인 건 두 가지였어요. **나중에 영어로도 쓰고 싶다**는 것, 그리고 **만드는 과정 자체가 이 블로그의 첫 콘텐츠**가 된다는 거예요. 지금 읽고 계신 이 시리즈가 바로 그 결과예요.

빨리 글부터 쓰고 싶다면 벨로그로 시작해서 나중에 옮기는 방법도 있다고 Claude가 알려 줬어요. 저는 어차피 만드는 과정을 쓰고 싶어서 처음부터 직접 만들었어요.

## 정리

- 주제가 다르면 블로그를 나누는 게 검색에도 독자에게도 좋아요.
- 나눌 때는 **독자가 겹치는지**를 기준으로 묶어요.
- 다국어나 나만의 기능이 필요하면 직접 만들기, 빨리 시작하고 싶으면 블로그 서비스예요.
