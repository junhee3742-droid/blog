지난 편에서 블로그를 "직접 만든다"는 게 내 땅에 내 집을 짓는 일이라고 했어요. 그런데 저는 설계도(코드)를 그릴 줄 몰라요.

> "그럼 집은 누가 지어?"

![고민](/stickers/thinking.svg)

오늘의 주인공이 바로 그 답이에요. 말만 하면 설계도를 그려 주는 건축가, **AI**예요. 이번 편에서는 AI에게 말로 부탁해서 블로그를 실제로 만든 과정을 보여 드릴게요!

## 바이브 코딩이 뭐예요?

**바이브 코딩**(Vibe Coding)은 코드를 직접 쓰는 대신, AI에게 원하는 걸 **말로 설명해서** 프로그램을 만드는 방식이에요.

예전에는 이랬어요.

- 프로그래밍 언어를 배운다 → 코드를 한 줄 한 줄 쓴다 → 오류를 찾아 고친다

바이브 코딩은 이래요.

- "이런 블로그가 있으면 좋겠어"라고 말한다 → AI가 코드를 쓴다 → 결과를 보고 "여기는 이렇게 바꿔 줘"라고 다시 말한다

집 짓기로 치면, 벽돌을 직접 쌓는 게 아니라 **건축가에게 원하는 집을 설명하고, 지어진 걸 보면서 고쳐 달라고 하는 것**이에요. 그래서 코딩을 몰라도 "어떤 걸 원하는지"만 분명하면 만들 수 있어요.

## 제 건축가는 Claude예요

이 블로그를 함께 만든 AI는 **Claude**(클로드)예요. Anthropic이라는 회사가 만든 AI예요.

Claude를 고른 이유는 단순해요. 그냥 대화만 하는 게 아니라, **제 GitHub 창고에 직접 코드를 올리고, 만든 사이트를 직접 열어서 확인까지** 해 줄 수 있었거든요. 제가 할 일은 원하는 걸 말하고, 결과를 보고, 필요한 버튼 몇 개를 누르는 것뿐이었어요.

(최근에 나온 OpenAI의 codex를 사용하셔도 괜찮아요!)

![아이디어](/stickers/idea.svg)

## 준비물: GitHub 창고 하나

집을 지으려면 설계도를 보관할 창고가 필요해요. 1편에서 말한 **GitHub**(깃허브)예요.

1. **github.com에서 가입해요.** 이메일만 있으면 무료로 만들 수 있어요.
2. **빈 저장소(Repository)를 하나 만들어요.** 저는 이름을 `blog`로 했어요. 오른쪽 위 **+** 버튼 → **New repository** → 이름 입력 → **Create repository** 순서예요.
3. **AI가 이 창고에 접근할 수 있게 연결해요.** Claude에서는 설정의 커넥터(Connectors)에서 GitHub를 연결하면 돼요.

## "블로그 좀 만들어 줘"라고 말했더니

저장소를 만들고 나서 제가 한 일은, 원하는 블로그를 설명한 것뿐이에요. 대략 이런 내용이었어요.

- 논문·과학 소식과 바이브 코딩·부업 이야기를 쓸 블로그
- 지금은 한국어로 쓰지만, **나중에 영어로도** 쓰고 싶음
- 글을 주제별로 나눠서 보여 주면 좋겠음

그러자 Claude가 **Astro**(아스트로)라는 도구로 블로그 기본 틀을 만들어서 제 `blog` 창고에 올려 줬어요. Astro는 블로그처럼 글 위주의 사이트를 빠르고 가볍게 만드는 도구예요.

만들어진 블로그에는 이런 게 들어 있었어요.

| 들어간 것 | 어떤 건지 |
| --- | --- |
| **한/영 주소 나누기** | 한국어는 `/ko/`, 영어는 `/en/`으로 나눠서, 나중에 영어 글만 추가하면 되게 해 뒀어요 |
| **카테고리 2개** | 지금의 "과학 · 연구 소식"과 "개발 · 부업"의 시작이에요 |
| **소개 페이지와 예시 글** | 화면이 잘 나오는지 보려고 넣은 글이에요. 이 예시 글이 나중에 첫 인사 글 "블로그를 시작하며"가 됐어요 |
| **글 쓰는 법 안내** | 새 글은 템플릿 파일을 복사해서 쓰면 된다고 한국어로 정리해 줬어요 |

제가 말로 설명한 건 몇 줄이었는데, 그 뒤에서 Claude가 수십 개의 파일을 만들었어요. 저는 그 코드를 한 줄도 읽지 않았어요. 그래도 블로그가 생겼어요!

![놀람](/stickers/surprised.svg)

## AI도 솔직하게 말해 줬어요

인상 깊었던 점이 하나 있어요. Claude가 코드를 다 올린 뒤에 이렇게 말했어요.

> "다만 **아직 한 번도 빌드해 보지 않은 상태예요.** 실제 빌드 확인은 첫 배포에서 하게 돼요."

빌드는 설계도를 보고 실제로 집을 지어 보는 과정이에요. 작업 환경의 제약 때문에 직접 지어 보지는 못했으니, 집이 잘 서는지는 땅(호스팅)에 올려 봐야 안다는 거예요. 다행히 첫 배포에서 오류 없이 **한 번에** 성공했어요.

AI가 "다 됐어요!"라고만 하지 않고, **확인한 것과 확인 못 한 것을 나눠서** 말해 주니까 오히려 더 믿음이 갔어요.

## 블로그 이름도 같이 정했어요

블로그 이름은 처음에 임시로 "연구와 코딩 노트"였어요. 이름을 고민하다가 다른 AI인 Gemini(제미나이)에게 물어봤더니 **AutoVibe Lab**을 추천해 줬어요. 그래서 Claude에게 어떠냐고 물었더니, 좋은 점과 걸리는 점을 나눠서 알려 줬어요.

- **좋은 점:** 영어라서 나중에 영어 블로그로 확장할 때 그대로 쓸 수 있고, "Lab"은 연구자라는 정체성과, "Vibe"는 바이브 코딩과 잘 맞아요.
- **걸리는 점 1:** "Auto"는 영어권에서 자동차로 먼저 읽혀요. 실제로 검색해 보니 같은 이름의 자동차 용품 상점이 이미 있었어요.
- **걸리는 점 2:** 자동화와 코딩은 드러나는데, 논문·과학 쪽은 이름에 안 보여요.

그리고 대안으로 **Vibe Lab Notes**, Neuro Vibe Lab, Lab & Code를 제안했어요. 저는 연구 노트와 바이브 코딩을 둘 다 담은 **Vibe Lab Notes**가 마음에 들었고, 그 자리에서 바로 블로그 이름이 바뀌었어요. 지금 보고 계신 이 블로그예요!

## AI에게 부탁할 때 도움이 됐던 것

직접 해 보니 AI에게 잘 부탁하는 요령이 몇 가지 있었어요.

1. **"무엇을"보다 "왜"를 말해요.** "영어 페이지 만들어 줘"보다 "나중에 영어로도 쓰고 싶어"라고 하니까, 처음부터 한/영 구조로 설계해 줬어요.
2. **모르는 건 그냥 물어봐요.** "깃허브가 뭐야?"와 같은 엉뚱한 질문도 괜찮아요. AI가 상황을 확인하고 알려 줘요.
3. **의견을 물어봐요.** 이름처럼 정답이 없는 것도 "네 생각은 어때?"라고 물으면 장단점을 정리해 줘요. 결정은 제가 해요.
4. **결과를 직접 확인해요.** AI가 "확인 못 했다"고 한 부분은 꼭 직접 보고 넘어가요.

## 다음 편 예고
